# Ego 志愿认证准备验证

对应 #6，接口为纯 SDK `buildVolunteerCertificationPreparation`、Node SDK `prepareVolunteerCertificationInEgo` 与 `friends drafts prepare`。

## 执行边界

- Node SDK 重新查询学校，校验账号/身份单位/组织/活动、选中名单的报名 UUID、岗位及手动添加人员；不能把调用者传入的 source 当作权限证明。
- 页面身份、活动 UUID 和认证类型再次核对。仅允许对应已打开页面，或明确选定的空白标签页。已有页面不会被导航覆盖。
- 页面执行器只使用 Ego 文档支持的 `snapshot/evaluate/click/fill/waitForSelector/waitForFunction` 等接口；没有 Playwright、隐藏提交 API、表单 submit、全部认证或最终提交点击。
- 读取前端可见状态，保留较新的人工时长、额外勾选和无法唯一识别的人员。仅当当前值仍与学校原始值一致时才应用草稿修改；打开编辑器后再核对时长，防止检查后发生的新修改被覆盖。
- 局部保存只使用当前生产源码已核实的 AddStu `.set-form .footer` 或 SetStu `.van-popup--center .save` 按钮；审批页面全局保存不在此流程内。
- `dry-run` 只验证和读取，不导航/点击/上传/交接。实际准备结束后才 `handOff`，交接后不再读取或操作页面。部分操作中断保留 UNKNOWN_OUTCOME 和已完成动作，由人工核查，不自动重试。

## 已运行

受控 SDK 和真实 CLI 进程调用真实 SDK。jsdom 驱动虚构页面真实事件处理程序，严格限制 Ego 协议，只能使用已文档化的方法，并检查交接后不再操作、无意导航失败、最后提交请求为零。覆盖已有人员改时长、添加人员/选岗位/局部保存、明确勾选、人工变化与中途变化、错误学校账号、dry-run、所有 Ego submit 绕过选项及版本化 JSON。

## 保留限制

同名人员无法从列表可见名字唯一对应学号时，保留为待人工处理，绝不猜测。页面当前无认证附件控件，带材料草稿会在写入前拒绝。学校真实人工提交和最终认证回查未执行；#8 的独立 API 提交不用于自动完成 Ego 任务。

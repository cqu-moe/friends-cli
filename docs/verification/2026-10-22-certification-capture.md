# 志愿认证人工修改捕获验收

## 公开契约

- Node SDK：`captureVolunteerCertificationFromEgo`。要求 `userReturnedControl:true`、现有 task/page、草稿与预期修订；先恢复明确交还的控制，再重新读取页面会话，并向学校重新核验账号、身份单位、组织与活动。
- CLI：`friends drafts capture <id> --via ego --ego-task-space <n> --ego-page <p> --expected-revision <n> --user-returned-control`。不接受 `--yes` 替代交还控制。
- 捕获逐项打开本地“设置时长”弹窗，读取可见学号、姓名、岗位与时长，再关闭而不保存。结果写入既有私有草稿存储的新修订；修订冲突保留候选冲突文件。
- 未完成编辑弹窗、页面缺失人员、未知岗位、未填时长与网页不可恢复材料如实报告。此认证表单没有材料控件，已有材料引用保留并标记待处理；不会上传或声称已恢复附件。
- 捕获不恢复录入、不最终提交。恢复必须另行选择草稿修改后调用 `drafts prepare`；提交后只用 `certification status` 回查，不补点最终按钮。

## 受控 SDK 与真实 CLI

实际执行 Ego 生成脚本的 DOM fixture 保留页面行及控制权，覆盖 prepare→handOff→人工修改状态→显式返回→capture→新修订→冲突→单独 prepare。SDK 和真实命令进程分别验收，不替换 SDK 内部流程。HTTP 服务独立统计最终提交。

覆盖错误账号/活动、未交还控制、未完成编辑、材料不可恢复、缺失人员、过期修订及外部行为产生的认证状态变化。状态回查通过 SDK 与 CLI 读取，不在测试里自动点击最终按钮冒充人工提交。

## 实际 Ego

2026-10-22 在安装的 Ego 2.1.0 中运行真实 CLI prepare，虚构页面两行录入后实际 handOff。用户将第一人从 1.5 小时改成 2 小时并明确交还；真实 CLI capture 保存到修订 2，时长为 2/3 小时。之后用户授权 Agent 自行操作测试，Agent 取消第二人选择，再 capture 为修订 3，仅第一人入选。独立本地 HTTP 服务最终提交计数为 0。

初版虚构页只有 checkbox 语义而没有可见标识，用户指出后补上可见方框、勾选图形、已选中/未选中文案与键盘操作，并实际截图检查。不能把 DOM 语义检查当作视觉验收。

真实运行还检出并修复：`evaluate` 显式 undefined 参数不被接受；遮罩默认中心被弹窗覆盖，需点击露出的角落；直接移动页会话不能依赖 SSO iframe；隐藏加载 Toast 会造成泛用弹窗等待歧义。对应 SDK 回归先失败再修复。
